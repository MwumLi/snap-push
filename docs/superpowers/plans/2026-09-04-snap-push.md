# snap-push 实现计划

> **For agentic workers:** 本计划采用 superpowers:subagent-driven-development 逐任务执行。步骤使用 `- [ ]` 勾选跟踪。

**目标：** 实现本地截图推送服务 snap-push（详见设计文档 `docs/superpowers/specs/2026-09-04-snap-push-design.md`）。

**架构：** Node 零依赖单文件 `server.js`（内嵌前端页面），本机落盘 `SNAP_PUSH_DIR`（默认 `/tmp/snap-push`，`<md5>-原名` 命名）用于预览；选中远程服务器时经 ssh 探测妙传 → rsync（scp 兜底）同步。

**技术栈：** Node.js ≥ 18（本机 v24），仅标准库；测试用 `node:test`（零依赖）。

---

## 任务拆分（3 个任务，串行执行）

### 任务 1：后端 server.js（接口 + 同步逻辑 + 测试）

**Files:**
- Create: `server.js`（骨架 + 全部 API + 同步执行器，页面占位返回简单 HTML 即可，任务 2 再替换）
- Create: `test/server.test.mjs`

**实现要点（详见设计文档第 4/5/7/8 节）：**

1. 常量与环境：`HOST`(默认 127.0.0.1)、`PORT`(默认 8123)、`SNAP_PUSH_DIR`(默认 /tmp/snap-push)、`MAX_BODY`(20MB)、子进程超时 30s。
2. 纯函数（可单测）：
   - `md5Name(bytes, orig)` → `<md5hex>-<basename(orig)>`
   - `sanitizeOrigName(raw)` → 仅取 basename、仅保留 `[A-Za-z0-9._-]`、去首尾空白；空则 `image.png`
   - `validateHost/validateUser/validateDir/validateFileName` → 白名单校验（设计文档 5.1）
   - `mimeOf(name)` → png/jpg/jpeg/gif/webp/svg/bmp → Content-Type，默认 `application/octet-stream`
3. 子进程封装 `run(cmd, args, timeoutMs)` → `spawn` 参数数组（**不用 shell**），超时 kill，resolve `{code, stdout, stderr}`，超时/错误抛中文 Error。
4. 同步执行器 `syncToRemote(localPath, name, {host, user, dir})`：
   - ssh 探测 `mkdir -p + test -f`（EXISTS→skip）
   - rsync；stderr 含 `not found` → scp 兜底
   - 返回 `{method}` 或抛中文错误
5. HTTP 路由：
   - `GET /` → 页面（此任务先返回占位 HTML）
   - `GET /health` → `{"ok":true}`
   - `POST /upload?name&host&user&dir&urlBase` → 收字节（限制 20MB）→ md5Name → 落盘本机（已存在跳过写入）→ host 空：`method:'local'`；否则 syncToRemote → JSON `{ok, localName, remotePath, url?, method}`（remotePath = `dir/<name>`，url = `urlBase + '/' + name`；本机时 remotePath = 本机绝对路径）
   - `GET /api/library` → 列 `SNAP_PUSH_DIR` 中 `<32hex>-` 前缀文件 `{name,size,mtime}`
   - `GET /files/<name>` / `DELETE /files/<name>` → 校验 name 匹配 `^[0-9a-f]{32}-[A-Za-z0-9._-]+$`（防穿越），读/删本机文件
   - 404 兜底；错误统一 `{"ok":false,"error":"中文信息"}` + 4xx/5xx
6. 导出 `createServer()`（可注入 `snapDir`）与 `start()`；`import.meta.url === process.argv[1]` 判断才自动启动（直跑 `node server.js` 起服务，测试 import 不起服务）。

**测试（test/server.test.mjs，node:test + 临时目录）：**
- md5Name/校验函数/mimeOf 纯函数断言（合法、非法、路径穿越、空名默认）
- 启动测试服务器（随机端口 + `os.tmpdir()` 下临时 snapDir）：
  - `/health` 200
  - `POST /upload`（无 host）→ 文件落盘、返回 localName/remotePath/method=local；重复上传同字节 → 仍 ok（幂等）
  - `GET /api/library` 包含该文件；`GET /files/<name>` 字节与 Content-Type；`DELETE` 后 library 为空
  - `name` 非法（含 `/`、`..`）→ 400
  - 超过 20MB → 413（可用小 MAX_BODY 注入测边界更简单：构造大 buffer 或注入小上限均可）
  - `GET /files/../etc/passwd` → 400/404，不泄露文件
- 远端同步执行器：单测失败分支（不可达 host 用 `127.0.0.1:1` 之类必然失败 → 返回中文错误）；rsync/scp 成功路径若本机有 sshd 则做可选真测（环境变量 `SNAP_PUSH_E2E=1` 才跑，默认跳过）

**验证：**
- [ ] `node --check server.js` 通过
- [ ] `node --test test/` 全绿
- [ ] `node server.js` 手起一次 `/health` 通（Ctrl+C 退出）
- [ ] git commit

### 任务 2：内嵌前端页面

**Files:**
- Modify: `server.js`（替换 `GET /` 占位为完整内嵌页面）

**实现要点（详见设计文档第 6 节）：**

1. 单页 HTML/CSS/JS 模板字符串，无外部资源，简洁可用即可（卡片式布局）。
2. 目标下拉：`本机（默认）` + localStorage(`snap-push.servers`) 的服务器列表；「⚙ 管理」面板增/改/删（昵称可选/IP/用户名默认 root/目录默认 /tmp/snap-push/URL 前缀可选），变更后刷新下拉。
3. 上传区：`<input type="file" multiple accept="image/*">` + 拖拽 + `paste` 事件（截图 Ctrl+V）。逐文件 `fetch POST /upload`（query 带 name 与当前目标参数），显示每个文件的成功（路径/URL/方式）或失败（中文错误），成功后刷新历史。
4. 历史区（按当前目标过滤）：`GET /api/library` + localStorage(`snap-push.history`，结构见设计文档 6.3）。选中服务器 → 只显示该服务器（host+dir 匹配）记录；本机 → 全部。缩略图 `GET /files/<name>`；每条记录显示路径/URL/时间/方式 + 复制按钮；「删除」调 `DELETE` 后刷新并清该文件记录。
5. 对账：加载时本机不存在的文件清掉其 history 记录。
6. 复制用 `navigator.clipboard.writeText`，失败回退 `document.execCommand` 兼容。
7. 代码带中文注释、符合人类阅读习惯（与任务 1 一致的注释风格）。

**验证：**
- [ ] `node --check server.js` 通过；`node --test test/` 仍全绿
- [ ] 手工：起服务 → 默认本机上传一张图 → 缩略图出现、路径可复制、`/tmp/snap-push` 落盘
- [ ] 手工：新增服务器配置 → 切换后历史过滤正确；上传（无真实远端时预期报中文错误）
- [ ] git commit
